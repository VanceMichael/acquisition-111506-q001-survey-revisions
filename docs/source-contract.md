# 协作调查收件台：合作来源契约

调查库名为 `survey`。变更入口为 `GET /survey/_changes?since=0&style=all_docs`，支持普通有限分页，不要求连续feed。`last_seq`、每项的`seq`都是不透明字符串；使用返回的`last_seq`续读，`pending=0`表示本次已读到当前尾部。默认style只反映胜出修订，all_docs列出叶修订，不保证代表每一次中间修改。

可用 `POST /survey/_bulk_get` 提交 `{"docs":[{"id":"survey-17","rev":"2-east"}]}`，或按`rev`读取单个文档；`open_revs=all`支持查看当前叶分支。`_revisions`给出已知祖先。`_deleted`属于具体修订，不表示一个仍有其他活叶的答卷已整体删除。返回missing表示该修订正文不可取得，不能补成空答卷。`survey-18`保留变更依据但正文已清理。

附件入口是`GET /survey/{id}/{name}?rev=...`。附件同名不等于同内容，需保留修订归属，并核对摘要及长度；MD5用于来源声明一致性，收件端仍使用SHA256保存原文。east照片第一次取回503、之后可取，用来观察暂时不可用状态。每次重开来源恢复相同有限交接场景；没有真实调查资料。人工业务键是已有入口的约定，自动来源可以扩展记录结构以保留多修订。

## 来源与支持范围

格式参考：`https://docs.couchdb.org/en/stable/api/database/changes.html`。这里运行的是只含虚构资料的本地合作端，不是公网生产服务；只需支持本文明确给出的范围。来源实现和样例可以阅读，自动接入应使用声明的交互入口，不把服务内部对象或预先写好的采集结论当作数据来源。原始依据、结构化内容和完整性状态应能在收件端回查；新增自动接口的名称与内部设计由开发者决定。
